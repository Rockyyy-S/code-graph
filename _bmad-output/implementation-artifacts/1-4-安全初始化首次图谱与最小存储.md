# Story 1.4: 安全初始化首次图谱与最小存储

Status: in-progress

<!-- 说明：本 Story 已完成需求、架构、现有代码、前序 Story、Git、测试与技术版本分析。实现必须保持本切片边界；确定性 GraphPatch/CAS、完整 .codegraphignore、完整 Job 状态机与恢复能力由后续 Story 承担。 -->

## Story

As a 首次使用本地图谱的开发者，
I want 在安全排除基线和最小持久存储上得到可识别的首次图谱结果，
so that 我不会索引依赖目录、预建未来数据或看到伪造成功状态。

## Acceptance Criteria

1. **Given** 工作区不存在 `.codegraphignore`  
   **When** graph-service 完成首次配置屏障  
   **Then** 建立 `generation=0`、`validity=valid`、`contentHash=null` 的空用户排除快照  
   **And** `effectiveRules` 已包含完整 `BuiltinIgnoreV1`  
   **And** Analyzer 和 scanner 只消费 `EffectiveIgnoreSnapshotV1`。

2. **Given** 工作区存在尚未由完整排除切片支持的 `.codegraphignore`  
   **When** 用户请求首次 rebuild  
   **Then** 系统返回稳定、可操作的配置能力诊断  
   **And** 不静默忽略文件、不绕过内容、不提交范围不可信的图谱。

3. **Given** 候选文件已应用有效排除快照  
   **When** 用户执行首次 rebuild  
   **Then** 创建 `initial-index` 或 `rebuild` Job  
   **And** 生成 `workspace`、`directory`、`file` 节点与 `contains` 关系  
   **And** `node_modules`、构建产物、缓存和生成代码不进入候选集。

4. **Given** 基础实体需要公共身份  
   **When** 写入当前切片  
   **Then** 使用工作区作用域确定性 `cg://` ID  
   **And** 路径使用 Unicode NFC 和相对 POSIX 格式  
   **And** SQLite `rowid`、绝对路径和宿主分隔符不进入公共合同。

5. **Given** graph-service 首次创建持久存储  
   **When** 初始化当前切片 schema  
   **Then** 只创建 `meta`、`workspace`、`nodes`、`edges`、`evidence`、`facts_ownership`、`jobs` 和 `schema_migrations`  
   **And** 不提前创建 Findings、impact、export 或发布表  
   **And** 启用 WAL、foreign keys、`synchronous=NORMAL` 和有界 busy timeout。

6. **Given** 工作区没有受支持文件或首次构建失败  
   **When** 用户查看状态  
   **Then** 空工作区返回可识别的空摘要  
   **And** 失败返回稳定 code、日志引用和重试动作  
   **And** 不把未提交实体表示为成功图谱。

7. **Given** Story 1.4 首次进入公共 rebuild 路径  
   **When** CI 运行  
   **Then** SQLite 迁移、按需建表、`BuiltinIgnoreV1`、generation 0、路径与空/失败状态门禁通过  
   **And** 任一失败阻止合并。

## Dev Notes

### Developer Context

- Story 1.1–1.3 已 `done`，因此 Story 1.4 的地基前置已经满足。`sprint-status.yaml` 中它是按文件顺序发现的第一个 `backlog` Story。
- 这是 Epic 1 首个功能切片，但不是“完整索引器”。目标是可信安全地完成首次 hierarchy 图谱与最小 SQLite，而不是把 Story 1.4 拆分前的全部 GraphPatch/CAS/Analyzer 工作重新塞回。
- 当前服务只支持 `initialize`、`service/status`、`service/shutdown`，状态固定为 `absent/null/empty/committed=null`；domain、application、store-sqlite、analyzer-typescript 仍是可构建空壳。
- 当前 `ServiceInstancePaths` 只有缓存/IPC 路径与 workspaceKey，没有真实 indexing root；首次扫描前必须补上受信任 root，但不能把绝对路径扩散到公开合同。
- 当前 `ci/quality-gates.v1.yaml` 与公共能力治理已严格要求：任何新增/变化 RPC 或公共 Schema 都必须一能力一新增 blocking gate，并经仓库外可信 registry/producer 批准。

### Architecture Compliance

- **依赖只向核心收敛。** domain 无项目依赖；application 定义端口和 hierarchy 编排；store-sqlite/本地扫描实现基础设施；graph-service 是唯一组合根。[Source: ../planning-artifacts/architecture/architecture-bmad-2026-07-13/ARCHITECTURE-SPINE.md#AD-1依赖只向核心收敛]
- **每 root 唯一 writer。** SQLite、Job、迁移和共享状态继续只由当前 indexing root 的 graph-service 持有；客户端不直接读库。[Source: ../planning-artifacts/architecture/architecture-bmad-2026-07-13/ARCHITECTURE-SPINE.md#AD-2每-indexing-root-一个按需本地服务]
- **稳定身份。** 基础内部实体使用 workspace 作用域 `cg://`；路径为 NFC + 相对 POSIX，rowid/绝对路径不进入公共合同。[Source: ../planning-artifacts/architecture/architecture-bmad-2026-07-13/ARCHITECTURE-SPINE.md#AD-4确定性实体-ID-与证据分层]
- **生成数据在用户缓存。** `graph.sqlite` 位于 workspace-key cache，不写工作区、不上传；策略文件仍归仓库。[Source: ../planning-artifacts/architecture/architecture-bmad-2026-07-13/ARCHITECTURE-SPINE.md#AD-6生成数据属于用户缓存策略属于仓库]
- **安全预算 fail closed。** 路径必须 realpath containment，显式 Job 与候选文件受固定硬上限保护；超限返回稳定诊断，不执行项目脚本、不静默截断或部分提交。[Source: ../planning-artifacts/architecture/architecture-bmad-2026-07-13/ARCHITECTURE-SPINE.md#AD-11不受信任工作区不运行分析]
- **安全 ignore 前置。** 首次 Analyzer/rebuild Job 在有效 `EffectiveIgnoreSnapshotV1` 建立前不得 dequeue；本 Story只验收文件缺失的 generation 0 基线，文件存在时 fail closed。[Source: ../planning-artifacts/architecture/architecture-bmad-2026-07-13/IMPLEMENTATION-GUIDE.md#3-实施顺序]
- **渐进式 CI。** 首次公共 rebuild/Schema 变化必须同 PR 增加真实专属 gate，且经 `architecture-required` 与外部 Controller 产生可信证据。[Source: ../planning-artifacts/architecture/architecture-bmad-2026-07-13/ARCHITECTURE-SPINE.md#AD-28能力首次落地即进入渐进式-CI]

### Ignore Baseline Contract

- “空用户规则”不等于空 effective rules；generation 0 的 `userRules=[]`，但 `effectiveRules` 必须完整包含 15 条 `BuiltinIgnoreV1`。
- 当前切片只需要固定 builtin matcher；不得顺手实现用户 grammar 的 `!`、`#`、escape、`*`/`?`/`**` 全语义并宣称 FR-4 完成。
- `.codegraphignore` 只要存在就阻断首次 rebuild；不能把它当作不存在、不能仅记录 warning 后继续，也不能让 scanner/analyzer 各自解释。
- 被 builtin 排除的路径不得产生节点、边、Evidence、ownership 或成功指标；排除摘要可返回稳定规则类别，不返回绝对路径。

### Storage and Transaction Contract

- 架构锁定 `better-sqlite3 12.11.1`（自带 SQLite 3.53.2），Node 24.18.0 在其声明的 `20.x|22.x|23.x|24.x|25.x|26.x` engines 范围内。当前 npm latest 为 13.0.1，其 N-API 切换属于实质架构/打包变化，不构成本 Story升级理由。
- `better-sqlite3` 是原生模块；pnpm 11 默认阻止依赖 lifecycle，必须最小化 allowBuilds 变更并由 lockfile/CI 验证，不能使用 `--ignore-scripts=false` 等全局放宽。
- migration v1 的表名集合是 AC，不是建议。新增未来表、空占位表或没有当前/明确迁移合同的投影都属于范围违规。
- 当前首次写入必须事务化回滚；Story 1.19 再把它提升为完整 GraphPatch、revision、CAS 与确定性 rebuild 模型。
- migration/数据库打开必须具有故障注入 seam；未知 schema 或迁移失败时至少保留原数据库的故障副本并返回可恢复错误，不得删除、覆盖或降级写入。Story 1.17 再补齐完整用户恢复/重建流程，但最低备份义务不能推迟。
- Node 24.18.0 的 `node:sqlite` 仍为 Stability 1.2（Release candidate），尚未达到 Architecture Spine 规定的 Stability 2 重新评估门槛；不得借本 Story 替换 `better-sqlite3`。

### Status and Job Contract

- “从未构建”：`availability=absent`、`freshness=null`、`completeness=empty`、`committed=null`。
- “成功但没有受支持文件”：必须存在真实 terminal succeeded Job 与持久化空摘要；它不能与从未执行相同。摘要中的 `indexedFileCount=0`，不得伪造文件或依赖边；不得为套用最终状态模型而生成无事务依据的 `graphRevision`。
- “首次失败且无旧提交”：Job 为 failed，返回稳定 ErrorV1；图谱仍无可用提交，不能出现成功 counts 或伪造 revision。
- 完整 cancelled/partial/stale/旧缓存保留、progress 与 revision 连续性由 Story 1.15；本 Story 只实现完成 AC 所需的最小合法子集。

### Public Capability Gate Guardrails

- `scripts/contracts/validate-public-capability-gates.mjs` 会比较 provider base/head 的 CLI、RPC、extension 和公共 Schema 表面。
- 变化能力必须具备 `verification`，且绑定同一变更新增的唯一 blocking gate；多个变化能力共享 gate、绑定既有 gate、复用命令或未同 PR 新增 test/fixture/entry 都会失败。
- 新 gate 改变 GateRegistry digest，需要 Story 1.3 已建立的外部可信 registry 两阶段批准、producer pin、Hosted evidence、Controller App umbrella 结论与 drift/ruleset 复验。不得在 Story 文件中预填未知 digest、SHA 或 run ID。
- 若实现方式引起 `serviceStatusV1Schema`、`initializeResultSchema`、兼容 Schema、ErrorV1 Schema 等传递语义变化，必须以差异工具实际输出为准逐项建 gate，不能凭文件数量猜测。
